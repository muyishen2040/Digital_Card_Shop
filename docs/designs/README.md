# Card design specifications

This folder holds maintained design specifications for shipped card experiences. These describe emotional intent, visual character, recipient interaction, accessibility and acceptance criteria. They remain useful after implementation; completed engineering plans belong in [the archive](../archive/README.md).

## General Cards

- [A Little Sunshine](a-little-sunshine.md): warm stationery, an envelope reveal and a personal letter.
- [Under the Same Sky](under-the-same-sky.md): distance and connection through a fold-open night-sky card.

## Birthday Cards

- [Make a Wish](make-a-wish.md): a candle-led birthday reveal and brief celebratory confetti.

## City Postcards

- [Collection design](../plans/city-postcard-design.md): the repeatable postcard layout and interaction.
- [Artwork playbook](../plans/city-postcard-artwork-playbook.md): creation and review of each city's artwork.

## Designing a new card

Begin with the [product brief](../PRODUCT_BRIEF.md) and [card design quality guide](../CARD_DESIGN_QUALITY.md). Study existing designs for **quality and specification depth**, not as templates to copy. General and Birthday Cards should have distinctive worlds and meaningful interactions, while City Postcards deliberately share one physical flip.

Use [Superpowers](https://github.com/obra/superpowers) brainstorming to establish feeling, character, world, reveal moment, signature detail, recipient journey, personalization, accessibility and acceptance criteria. Save the approved design specification here. Keep implementation steps and test plans in [`docs/plans/`](../plans/README.md).

Consult the [architecture](../ARCHITECTURE.md) and source code for actual integration boundaries. Design specifications capture intent; tests and the deployed implementation establish current runtime behavior.
